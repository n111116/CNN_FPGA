# DDR同帧视频延迟链路进度（2026-06-28）

## 目标
原来的顶层 `hdmi_loop` 中，YOLO 检测和 overlay 画框同步运行。由于 YOLO 有固定流水延迟，overlay 使用的是后一帧视频，导致框和裁剪子图来自检测帧之后的视频帧。

本次目标是在 overlay/crop 前加入 DDR 视频缓存：输入视频连续写入 DDR，等 YOLO 第一张特征图第一次 `new_line_out_1_layer7` 输出时，启动从 DDR 读取当前检测对应的视频帧，使画框和 LPRNet 裁剪使用与 YOLO box 同一帧的底图。

## 已完成的结构改动
- 新增 `rtl_pds/ddr/ddr_video_delay_sync.sv`，作为视频流到 DDR 再读出的同步模块。
- 新增 `rtl_pds/ddr/ddr_wr_line_ram.sv`、`rtl_pds/ddr/ddr_rd_line_ram.sv`，用于像素时钟域和 DDR 时钟域之间的行级缓存。
- 迁移 DDR 控制相关 RTL：`wr_cmd_trans.v`、`wr_ctrl.v`、`rd_ctrl.v`、`wr_rd_ctrl_top.v`、`sync_vg.v`。
- 迁移 PDS DDR IP `ddr3_test`，工程内使用 `prj_pds/ipcore/ddr3_test` 作为 PDS 工程 IP 路径。
- `rtl_pds/hdmi_loop.sv` 增加 DDR3 顶层端口和 `ddr_init_done`，并例化 `ddr_video_delay_sync`。
- overlay/crop 的输入视频已经从 HDMI 原始输入切换为 DDR 读出的 `ddr_video_vs/hs/de/rgb`。
- DDR 读取触发信号由 `new_line_out_1_layer7` 的每帧第一次输出产生，通过 toggle 跨到 DDR 逻辑。

## 当前实现策略
- 外部视频为 RGB888，写入 DDR 时压缩为 RGB565，读出后再扩展回 RGB888。精度损失可接受，DDR 带宽和容量压力更低。
- 当前按 1280x720@60Hz 参数接入：`H_ACT=1280`、`V_ACT=720`、`H_TOTAL=1650`、`V_TOTAL=750`。
- DDR 地址划分为两个 frame bank。它不是等待整帧写完再读的传统高延迟帧缓存，而是用于避免跨帧地址覆盖；读启动仍由当前帧的 YOLO 流水线标志触发，以保持低延迟。
- 写入侧按行收集，16 个 RGB565 像素打包为一个 256-bit beat，再按行 burst 写 DDR。
- 读取侧按行 burst 读 DDR，使用双行 buffer 给像素时钟域连续输出，恢复 720p 视频时序。
- 设计假设 YOLO 流水延迟稳定且小于半帧，`new_line_out_1_layer7` 触发读取时不会读到尚未写入的行。
